# Сервис рабочих программ (Work Program Service) — Вариант 13

## Номер варианта и название сервиса

**Вариант:** 13  
**Номер сервиса по списку:** 13 (Уровень 3 — Academic Planning)  
**Название сервиса:** Work Program Service (Сервис рабочих программ)

**Назначение сервиса:**  
Хранение файлов рабочих программ, привязка к дисциплине и специальности.  
Сервис отделен от других, так как файлы тяжелые и обновляются редко.

**Важно:** Сервис не хранит сведения, которые точно будут храниться в других сервисах (дисциплины и специальности хранятся в соответствующих сервисах).

## Добавить рабочую программу

### Информация, требуемая для создания рабочей программы

| Параметр | Пояснение | Обязательность | Тип | Ограничение | Значение по умолчанию |
|----------|-----------|----------------|-----|-------------|----------------------|
| discipline_id | ID дисциплины (из Discipline Service) | Да | integer | >0 | - |
| specialty_id | ID специальности (из Specialty Service) | Да | integer | >0 | - |
| file_url | URL-ссылка на файл рабочей программы | Да | string | max 500, валидный URL | - |
| file_name | Название файла | Да | string | 1-200 символов | - |
| file_size | Размер файла в килобайтах | Нет | integer | >=0 | 0 |

## Удалить рабочую программу по ID (мягкое удаление)

**Описание:**  
Вернет `true`, если рабочая программа была закрыта (удалена), иначе вернет `false`.  
Фактически запись из БД не удаляется, а реализуется через булевое поле `is_active = false`.

**Возвращаемое значение:** `boolean`

## ER-диаграмма

![ER-диаграмма](./erd.png)

### Описание ER-диаграммы

Диаграмма содержит следующие сущности и связи:

**1. Сущность `discipline` (Дисциплина)**
- `id` (PK) — первичный ключ
- `name` — название дисциплины
- `code` — код дисциплины
- `is_active` — статус активности

**2. Сущность `specialty` (Специальность)**
- `id` (PK) — первичный ключ
- `name` — название специальности
- `code` — код специальности
- `is_active` — статус активности

**3. Сущность `work_program` (Рабочая программа)**
- `id` (PK) — первичный ключ
- `discipline_id` (FK) — внешний ключ к discipline
- `specialty_id` (FK) — внешний ключ к specialty
- `file_url` — ссылка на файл
- `file_name` — имя файла
- `file_size` — размер в КБ
- `version` — версия программы
- `approved_by` — утвердивший
- `approval_date` — дата утверждения
- `description` — описание
- `is_active` — активность
- `created_at` — дата создания
- `updated_at` — дата обновления

**Связи:**
- `discipline` → `work_program`: **один ко многим** (одна дисциплина может иметь несколько рабочих программ)
- `specialty` → `work_program`: **один ко многим** (одна специальность может иметь несколько рабочих программ)

**Нормализация:**  
Все таблицы находятся в **третьей нормальной форме (3НФ)**.  
Связь «многие ко многим» между дисциплинами и специальностями реализована через таблицу `work_program`, которая является транзитивной (связующей) таблицей.

**Внешние ключи** не принимают значение NULL — обязательны при создании записи.
